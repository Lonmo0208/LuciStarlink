## 2. 我必须更正的三处（都有实测数据）

### 2.1 "block 光偏差根因是对象替换，实证 3 次 1 偏离 vs 0 次" —— 这不是我的数据

实测是：**换对象版 5 跑 3 偏；原地覆盖版 5 跑 2 偏**（噪声内）。也就是**原地覆盖没有修好那个偏差**。
"必须原地覆盖"我是**从线程模型推出来的硬要求**（光照线程会继续往它持有的对象里写，换对象等于把那些写送进
孤数组且无人重算），不是"偏差已定性/已修"。请按"推理得出的硬要求"引用它。

### 2.2 "7 对 / 6 偏"的偏差率是我给的，而且是**被污染**的 —— 现在应记为"测试方法问题已修复"，不是"已知 bug 未修"

三个让我两次收回结论的原因，现在都定位清楚了：

1. 探针第一版在服务端线程读**非线程安全**的光照存储（光照线程同时在写）→ 任何配置都读出不稳定值。
   已加**静默门**（连续 20 tick 无引擎工作才读），日志带 `quiesceTicks=` 自证。
2. **全列 block 指纹连 vanilla 自己都不可复现**（三次同配置两个同值一个异值；静置 120 s 后仍不同），
   根因是世界生成中岩浆/水这类时序依赖的方块变化（block 光敏感、sky 光不敏感）。已加**可选 y 范围**，
   判据限定在无流体气层。
3. **参考值会漂移**：每次运行都会重新保存世界，而 `haloPublish=false` / `adoption=false` 这类诊断跑会把
   世界改成另一种光照状态。所以"7 对 / 6 偏"混了不同世界的读数，**不能当偏差率用**（已撤回）。

受控条件下的完整数据：**连续 7 次运行 0 偏差**（1 次 vanilla + 6 次我们，含 y=100 平面**逐格 diff 为零**），
其中最后 3 次场景带**发光方块自检**（`execute if block … run say GLOW_*_YES`，六块全部在场）。
唯一那次被抓住的"偏差"（我们 `4d50732804a9a46d`，相邻 vanilla `61fb027e7d51ee31`）其光型与参考值
**完全相同、只是整体平移约 8 格**，而 sky 逐位一致 —— 这是**发光方块布局不同**，即我的场景在"被基准跑重建过的
世界"上 `setblock` 状态不可控，**不是引擎 bug**。

结论：**引擎侧 block 光分歧目前没有任何证据**。方法学此后固定为：相邻成对 + 场景自检 + 气层探针；
禁止跨世界/跨长序列比哈希。

### 2.3 "及时性是关键变量" —— 实测否

同一指标（per-pass min 中位，5 轮）下的四种调度：

| 方案 | per-pass min 中位 | 结论 |
|---|---|---|
| 默认（私有 drain + 250 µs 合并 + 异步） | 0.651 / 0.776（两批） | 基线 |
| 提前投递（绕过定时器，直接 `taskMailbox.tell`） | **1.114** | 更差 +44% |
| 合并窗口 2 ms | **1.049** | 更差 |
| tick 内同步等待提交（写入仍在光照线程） | **0.784** | 中性 |
| worldgen 只发核心区 | 0.756 | 中性（保留为可选开关） |
| 直装（跳过引擎吸收） | **0.599** | 唯一有效 |

即：**per-pass min 对"何时交活"不敏感，只对"交多少活"敏感**。250 µs 合并其实是**收益**（把一波发布合并成更少
drain 轮次），直接投递会把它们打散成一轮一次。

四档 per-pass min（本会话）：`sky_hole` 我们 0.651（5 轮）vs SL 0.593（3 轮）；`dense_chunk_patch` 1.872 vs
2.312/2.868；`block_toggle_border` 1.089 vs 1.794/2.386；`structure_cube` 1.781 vs 3.774/3.792。
**四档三胜，`sky_hole` 落后 ~10%**（wall 上 ~1.5×）。
